PrapsLib 2.0

Анимационный движок уровня GeckoLib для Luanti 5.17+ · glTF · IK · State Machine · Мультиплеер

Это полная документация Все API, рецепты, известные конфликты и рекомендации по интеграции. Если ты только начинаешь — читай сверху вниз, 20 минут хватит. Если чинишь баг — прыгай в Troubleshooting.

Обзор

PrapsLib 2.0 — это полноценная система анимации персонажей для Luanti, вдохновлённая GeckoLib из Minecraft. Она парсит Bedrock-совместимые .animation.json, поддерживает множественные слои с аддитивным смешиванием, контроллеры, state machine, keyframe events, Molang, IK и сервер-авторитарную синхронизацию.

Зачем это нужно

Стандартный API Luanti set_bone_override позволяет проигрывать одну позу за раз. PrapsLib даёт:

  • Множественные клипы одновременно — ходьба + дыхание + атака
  • Плавные crossfade-переходы между анимациями
  • State machine с автоматическими переходами по условиям
  • События на кадрах — звуки, частицы, кастомные колбэки
  • Molang — математика прямо в JSON
  • Синхронизацию в мультиплеере с компенсацией задержки
  • IK-решатели для процедурных ног, рук, цепочек

Философия движка

PrapsLib — не медиатор, а движок. Он загружается последним, пишет bone override последним в globalstep, и его поза побеждает. Если в твоём моде есть конкурент (mobs_redo, playeranim) — это решается на уровне load order, а не через компромиссы внутри движка.

Возможности

Контроллеры

Аналог AnimationController: один клип на контроллер, множество одновременно, приоритеты и аддитивность

State Machine

Граф состояний с условиями, crossfade, параметрами (bool/float/trigger), any-state переходами

Molang

Математика в JSON: query.anim_time * 90, тернарники, свои queries

Keyframe Events

Звуки, частицы, кастомные колбэки в точный момент времени из Blockbench timeline

30+ Easing

Quad, Cubic, Back, Elastic, Bounce, Catmull-Rom, per-axis Bezier

IK Solver

2-bone analytic + FABRIK для цепочек. Процедурные ноги паука на рельефе

Мультиплеер

Сервер-авторитарная синхронизация с компенсацией задержки, sequence numbers

Quaternion Math

Slerp с anti-flip, euler↔quat, shortest_angle, wrap

Procedural

Value noise, FBM, look_at, raycast — для живых персонажей

glTF-ready

Полная совместимость с glTF-скелетами Luanti 5.10+

Поток данных

  1. Парсинг — parser читает JSON → структура bone/keyframe/easing/Molang
  2. Кэш — cache хранит распарсенные анимации по modname + entity_type
  3. State Machine — проверяет условия переходов, дёргает controller:set_animation
  4. Controller — сэмплирует keyframes, миксует transitions, отдаёт позу
  5. Animator — собирает позы со всех контроллеров, применяет bone override
  6. Net — рассылает команды клиентам, компенсирует задержку

Ключи сущностей

Все реестры используют entity:get_id() как ключ. Если у сущности нет ID (например, на клиенте), используется tostring(entity). Это гарантирует совпадение между сервером и клиентом.

          "rotation": {

2Регистрация сущности

local prapslib = prapslib

minetest.register_entity("mymod:goblin", {
  initial_properties = {
    visual = "mesh",
    mesh = "goblin.gltf",     -- glTF вместо b3d
    textures = {"goblin.png"},
  },

  on_activate = function(self, staticdata)
    prapslib.register_entity(self.object)
    prapslib.register_entity_data("mymod", "mymod:goblin")

    local m = prapslib.sm.create_locomotion(self.object, {
      idle = "idle", walk = "walk",
      run  = "run",  jump = "jump",
      breath = "breath",
    })
    self._machine = m
  end,

  on_step = function(self, dtime)
    local vel = self.object:get_velocity()
    local speed = math.sqrt(vel.x^2 + vel.y^2 + vel.z^2)
    self._machine:set_float("speed", speed)
    self._machine:set_bool("on_ground", true)
  end,

  on_deactivate = function(self)
    prapslib.unregister_entity(self.object)
  end,
})

Всё. Дальше движок сам:

  • Загрузит и распарсит анимации
  • Создаст контроллеры и слои
  • Будет переключать idle → walk → run → jump по скорости
  • Синхронизирует всех игроков в мультиплеере

glTF вместо b3d 5.10+

Luanti 5.10 завёз glTF 2.0 с поддержкой скелетной анимации. Это современный формат, экспорт из Blockbench напрямую, без костылей в Blender.

Экспорт из Blockbench

  1. Открываешь модель, выбираешь File → Export → glTF
  2. В настройках экспорта:
ПараметрЗначениеПочему
FormatglTF Binary (.glb)Один файл, быстрее грузится
Model Export Scale1.6Пересчёт пикселей Blockbench → единицы Luanti (см. ниже)
Include Animations✅Вся вкладка Animate попадёт в файл
Include Empty Parents✅Иерархия скелета сохранится
Bake Animations❌Оставляй ключевые кадры, движок сам интерполирует
Compress❌Luanti не читает Draco-сжатие
Luanti игнорирует CUBICSPLINE Из glTF-формата Luanti понимает только LINEAR и STEP интерполяцию. Твои cubic-bezier кривые из Blockbench в glTF не перенесутся. Решение — использовать easing на стороне PrapsLib (см. easing), но это работает только если ты сам конвертируешь keyframes, а не отдаёшь glTF движку напрямую.
Матричные ноды нельзя анимировать Если в glTF узел имеет transform в виде matrix (а не translation + rotation + scale), Luanti не даст наложить на него bone override. Проверь в Blockbench: правый клик по кости → Reset Transform, потом пересохрани.

Ограничения glTF в Luanti 5.17

ОграничениеОбход
Нет CUBICSPLINEСвои easing-кривые в PrapsLib
Нет матричных нодReset Transform перед экспортом
Максимум 4 кости на вершину (weights)Стандарт для игровых моделей, обычно OK
Нет морф-таргетов (blend shapes)Bone override или shape keys через несколько мешей
Нет multiple animations в одном клипеКаждый клип — отдельный файл или PrapsLib mixer

Масштабы и позиции

Это самая частая причина «почему у меня модель гигантская» или «почему кости в 16 раз дальше чем надо».

Три системы измерения

ГдеЕдиницаОтношение
Blockbench (модель)пиксели (cube units)16 px = 1 блок
Blockbench (glTF export)метры glTF1 блок = 1 glTF unit
Luanti (glTF import)ноды10 glTF units = 1 нода

Итоговая формула

Blockbench: 16 px = 1 block
glTF:       1 block = 1 unit  (по спецификации)
Luanti:     10 units = 1 node

→ 16 px в Blockbench = 1 block = 10 units = 1 node в Luanti

Что делать

Model Export Scale = 1.6 Это единственное число, которое нужно помнить. Blockbench сам пересчитает все пиксели в единицы glTF так, чтобы в Luanti модель была ровно того размера, что ты видишь в Blockbench.

Анимации костей

Позиции костей в .animation.json от Blockbench тоже в пикселях (16 = 1 блок). Твой animator.lua делит их на 16 (POSITION_SCALE = 1.0 / 16.0). Это правильно для обеих моделей — b3d и glTF — при условии что модель экспортирована с правильным масштабом.

-- animator.lua
local POSITION_SCALE = 1.0 / 16.0

-- position из JSON в пикселях → block units для Luanti
override.position = { vec = {
    x = position[1] * POSITION_SCALE,
    y = position[2] * POSITION_SCALE,
    z = position[3] * POSITION_SCALE,
}, absolute = false }
Если модель в Blockbench в блоках, а не пикселях Если ты строишь модель «в блоках» (например, 2×3×1), то деление на 16 сломает позиции. В этом случае либо строй в пикселях (32×48×16), либо поменяй POSITION_SCALE = 1.0.

Формат JSON

PrapsLib использует Bedrock Animated Model-совместимый формат. Модели из Blockbench с экспортом Bedrock Entity работают из коробки.

Структура файла

{
  "format_version": "1.8.0",
  "animations": {
    "<имя_анимации>": {
      "loop": "loop" | "play_once" | "hold_on_last_frame",
      "animation_length": 1.5,
      "interpolation": "linear" | "cubic" | "catmullrom",
      "bones": {
        "<имя_кости>": {
          "rotation": { /* keyframes */ },
          "position": { /* keyframes */ },
          "scale":    { /* keyframes */ }
        }
      },
      "sound_effects": {
        "0.4": { "effect": "mymod:step" }
      },
      "particle_effects": {
        "0.6": { "effect": "mymod:dust" }
      },
      "timeline": {
        "1.2": [
          { "type": "custom", "data": "deal_damage" }
        ]
      }
    }
  }
}

Все формы keyframe

// 1. Одиночное значение на t=0
"rotation": [0, 0, 0]

// 2. Явные ключевые кадры
"rotation": {
  "0.0": [0, 0, 0],
  "0.5": [45, 0, 0],
  "1.0": [0, 0, 0]
}

// 3. С pre/post (Bezier control points)
"rotation": {
  "0.5": {
    "pre":  [10, 0, 0],
    "post": [80, 0, 0],
    "easing": "easeOutQuad"
  }
}

// 4. Molang-выражение
"rotation": ["query.anim_time * 90", 0, 0]

Полный пример: босс с фазами

local function register_boss()
  minetest.register_entity("mymod:dragon", {
    initial_properties = {
      visual = "mesh",
      mesh = "dragon.gltf",
      textures = {"dragon.png"},
      physical = true,
    },

    on_activate = function(self, staticdata)
      prapslib.register_entity(self.object)
      prapslib.register_entity_data("mymod", "mymod:dragon")

      local m = prapslib.sm.register(self.object, "combat")

      m:add_state("idle", {
        layers = {
          { controller = "main", anim = "dragon_idle" },
          { controller = "breath", anim = "dragon_breath",
            blend = "additive", weight = 0.4 },
        },
        transitions = {
          { to = "walk", when = function(ctx) return ctx.speed > 0.1 end,
            duration_ticks = 8 },
          { to = "roar", when = function(ctx) return ctx.aggro end,
            duration_ticks = 3, priority = 10 },
        },
      })

      m:add_state("walk", {
        layers = {
          { controller = "main", anim = "dragon_walk" },
          { controller = "breath", anim = "dragon_breath",
            blend = "additive", weight = 0.7 },
        },
        transitions = {
          { to = "idle", when = function(ctx) return ctx.speed <= 0.1 end,
            duration_ticks = 8 },
          { to = "fly", when = "!on_ground", duration_ticks = 5 },
        },
      })

      m:add_state("roar", {
        layers = {
          { controller = "main", anim = "dragon_roar",
            loop = "hold_on_last_frame" },
        },
        transitions = {
          { to = "idle", when = function(ctx)
              return ctx.time_in_state > 2.5
            end, duration_ticks = 8 },
        },
        events = {
          on_enter = function(entity)
            minetest.sound_play("dragon_roar", {
              object = entity, gain = 1.0
            })
          end,
        },
      })

      m:set_initial("idle")
      m:force_state("idle", 0)

      -- Keyframe events из JSON (звук шагов)
      prapslib.keyframes.set_sound_handler(
        self.object, "main", prapslib.keyframes.auto_sound_handler
      )

      self._machine = m
    end,

    on_step = function(self, dtime)
      local vel = self.object:get_velocity()
      local speed = math.sqrt(vel.x^2 + vel.z^2)
      self._machine:set_float("speed", speed)
      self._machine:set_bool("aggro", self.aggro or false)
    end,
  })
end

API: prapslib

Главный модуль. Загружается как глобальная таблица после инициализации мода.

prapslib.register_entity(entity) → id

Регистрирует объект в реестре движка. Вызывай в on_activate. Регистрирует в animator + net.

prapslib.unregister_entity(entity)

Убирает из реестра. Вызывай в on_deactivate.

prapslib.register_entity_data(modname, entity_type) → data | nil, err

Загружает анимации из modname/prapslib/<entity_name>.animation.json. Fallback: entity.animation.json. Результат кэшируется.

prapslib.play_animation(entity, animation_name, options) → state

Простой one-shot запуск. Для сложного — используй controller или sm.

options: mode, speed, loop, blend_time, interpolation

prapslib.stop_animation(entity)
prapslib.reset_bones(entity)
prapslib.is_playing(entity) → bool
prapslib.get_animation_time(entity) → number
prapslib.clear_cache()

API: controller

Аналог AnimationController из GeckoLib. Один контроллер = один активный клип за раз. Множество контроллеров = одновременная игра разных клипов.

controller.register(entity, name, transition_ticks, state_handler) → ctrl

Создать контроллер. Если с таким именем уже есть — вернёт существующий.

state_handler: (entity_state, ctrl) → "play", anim_name | "stop", вызывается каждый tick.

controller.get(entity, name) → ctrl | nil
controller.get_all(entity) → table
controller.clear(entity)
controller.clear_by_key(entity_key)
controller.update_all(entity, dtime, entity_state)
controller.build_pose(entity, ctx) → pose

Собирает финальную позу со всех контроллеров, применяя приоритеты и аддитивность.

Методы экземпляра

API: state_machine

Граф состояний с автоматическими переходами. Аналог Unity Animator.

sm.register(entity, name) → Machine
sm.get(entity, name) → Machine | nil
sm.remove(entity, name)

Если name == "*" или nil — удаляет все машины сущности.

sm.update_all(dtime)

Вызывается из globalstep автоматически.

Методы Machine

m:add_state(name, def)
{
  layers = {
    { controller = "main", anim = "walk",
      weight = 1, blend = "override", mask = {head = true} },
    { controller = "breath", anim = "breathe",
      weight = 0.3, blend = "additive" },
  },
  speed = 1.0,
  transitions = {
    { to = "run", when = function(ctx) return ctx.speed > 4 end,
      duration_ticks = 5, priority = 0 },
    { to = "attack", when = "is_attacking && !is_stunned",
      duration_ticks = 2, priority = 100 },
  },
  events = {
    on_enter  = function(entity, prev) end,
    on_exit   = function(entity, next) end,
    on_update = function(entity, dtime, state) end,
  },
}
m:add_any_transition(def)

Переход из любого состояния. Полезно для атаки / смерти / стана.

m:set_initial(name)
m:force_state(name, duration_ticks)
m:set_bool(name, val)
m:set_float(name, val)
m:set_int(name, val)
m:trigger(name)

Триггер живёт один tick, потом сбрасывается.

m:get_param(name) → any
m:get_current_name() → string
m:is_transitioning() → bool
m:pause() / m:resume()
m:add_listener(fn)

Вызывается при каждой смене состояния: fn(entity, new_state, old_state).

Рецепт: Паук на IK beta

Полностью процедурная локомоция — ноги сами подстраиваются под рельеф через raycast + IK.

Как это работает

  1. Rest position — где нога «хочет» стоять относительно тела
  2. Raycast вниз — находит реальную землю под rest-позицией
  3. Step trigger — если нога уехала от rest — стартует шаг
  4. 2-bone IK — считает углы бедра и колена до цели
  5. Gait — ноги делятся на 2 группы, шагают поочерёдно

Конфиг

spider_legs.configure(entity, {
  body_height = 1.0,
  step_trigger_distance = 1.0,
  ground_search_up = 3.0,
  ground_search_down = 5.0,
  legs = {
    { bone_upper="leg_l1_up", bone_lower="leg_l1_low",
      hip_offset={x=-0.4, y=0, z=0.6},
      rest_offset={x=-1.5, y=-0.8, z=1.5},
      a=1.0, b=1.0, group=0,
      step_duration=0.22, step_height=0.4 },
    -- ... 7 остальных ног
  },
})

Цикл в on_step

on_step = function(self, dtime)
  spider_legs.update(self.object, dtime)
  -- Движение тела — по твоему усмотрению
end
Порядок осей Если ноги крутятся не туда — поменяй {x = hip_pitch, y = hip_yaw, z = 0} на {x = hip_yaw, y = hip_pitch, z = 0}. Зависит от иерархии костей в модели.

Рецепт: Реанимация игрока экспериментально

Игрок в Luanti — это ObjectRef. Полноценно анимировать можно, если заменить visual на mesh/glTF.

Шаги

1Заменить визуал

minetest.register_on_joinplayer(function(player)
  player:set_properties({
    visual = "mesh",
    mesh = "mymod_character.gltf",
    textures = {"character_skin.png"},
    visual_size = {x=1, y=1, z=1},
    collisionbox = {-0.3, 0.0, -0.3, 0.3, 1.8, 0.3},
    stepheight = 0.6,
  })
end)

2Зарегистрировать в PrapsLib

minetest.register_on_joinplayer(function(player)
  prapslib.register_entity(player)
  prapslib.register_entity_data("mymod", "mymod:player")

  local m = prapslib.sm.create_locomotion(player, {
    idle = "player_idle", walk = "player_walk",
    run  = "player_sprint", jump = "player_jump",
  })
  player._anim_machine = m
end)

minetest.register_on_leaveplayer(function(player)
  prapslib.unregister_entity(player)
end)

3Параметры через globalstep

minetest.register_globalstep(function(dtime)
  for _, player in ipairs(minetest.get_connected_players()) do
    local m = player._anim_machine
    if m then
      local vel = player:get_velocity() or {x=0, y=0, z=0}
      local hspeed = math.sqrt(vel.x^2 + vel.z^2)
      m:set_float("speed", hspeed)
      m:set_bool("sprinting", player:get_player_control().aux1 and hspeed > 2)
    end
  end
end)

⚠️ Конфликты

Правда жизни В Luanti нет «слоя анимаций» как в Unity/Godot. Есть один глобальный set_bone_override — кто первый его дёрнул, того и поза. Last-write-wins. PrapsLib пишет последним в globalstep, поэтому его поза побеждает. Это by design.

Решения по каждому

playeranim

Обе библиотеки пишут в одни кости игрока. Решение: отключить playeranim для PrapsLib-игроков, либо добавить в playeranim проверку if entity._prapslib then return end.

mobs_redo

mobs_redo пишет set_animation в своём on_step, PrapsLib — в globalstep. PrapsLib победит, потому что globalstep идёт после. Решение: использовать mobs_redo только для AI, а анимации — через PrapsLib. Или обернуть:

local orig = mob_class.set_animation
function mob_class:set_animation(...)
  if self._prapslib_anim then return end
  return orig(self, ...)
end

wielditem / предмет в руке

Стандартная логика Luanti дёргает Right_Arm каждый кадр. Решение: использовать в модели имена костей Right_Arm и Wield_Origin — тогда wielditem сам привяжется корректно. Если кости названы иначе — предмет не будет виден.

3d_armor

Броня крепится к стандартным костям. Решение: использовать стандартные имена Body, Head в своей модели. Если у тебя кастомные имена — придётся патчить 3d_armor или отказаться от него.

skinsdb

Меняет только текстуры, не трогает кости. Решение: конфликтов нет, если skinsdb не перезаписывает visual. Если перезаписывает — применить set_properties после skinsdb (в minetest.after(1)).

Кастомные on_step в entity

Если в on_step пишешь свой set_bone_override — он перетрётся PrapsLib. Решение: используй prapslib.controller.register с priority > 0 или зарегистрируй callback через PrapsLib.

Стратегии разрешения

1. Load order

PrapsLib должен грузиться последним. В mod.conf других модов: optional_depends = prapslib — и PrapsLib автоматически поднимется после них.

2. Namespace-конвенция

Обяжи пользователей PrapsLib использовать префикс в именах костей:

praps_leg_upper
praps_leg_lower
praps_head

Тогда чужой мод, дёргающий head или Right_Arm, физически не тронет твои кости.

3. Медиатор через PrapsLib

Расширь API так, чтобы другие моды регистрировали свои слои через тебя, а не писали напрямую:

prapslib.controller.register(entity, "third_party_mod", 0, function(state)
  return "play", "their_anim"
end)

Это правильный путь, но требует PR в mobs_redo/playeranim.

4. Reapply в after()

Если конкурент пишет в on_step, а ты в globalstep — ты всегда последний. Если наоборот — используй:

minetest.after(0, function()
  prapslib.animator.update_all(dtime)  -- reapply поверх
end)

Рекомендации

Для автора мода с PrapsLib: если ты выпускаешь мод с PrapsLib, ставь depends = prapslib в mod.conf, а не optional_depends. Иначе пользователи могут запустить мод без движка.

Что делать правильно

  • ✅ Загружай PrapsLib последним через optional_depends в других модах
  • ✅ Используй один префикс костей — либо стандартные имена Luanti (Right_Arm), либо свой (praps_*), не смешивай
  • ✅ Не пиши свой set_bone_override если используешь PrapsLib — регистрируй через controller
  • ✅ Синхронизируй через net если у тебя MP — иначе клиенты рассинхронятся
  • ✅ Используй glTF, а не b3d для новых моделей — экспорт из Blockbench напрямую
  • ✅ Масштаб 1.6 в Blockbench — забудь про ручной пересчёт
  • ✅ Не трогай visual после register_entity — сломаешь скелет
  • ✅ Проверяй entity:get_pos() на nil перед вызовом методов

Чего НЕ делать

  • ❌ Писать obj:method and obj:method() — крашит Lua 5.1
  • ❌ Использовать <<, >>, &, |, ~ бинарные — нет в LuaJIT
  • ❌ Вызывать minetest.get_server_info — может быть nil
  • ❌ Использовать player:is_connected() — метода не существует
  • ❌ Перезаписывать visual после регистрации
  • ❌ Пытаться анимировать матричные glTF-ноды
  • ❌ Ставить CUBICSPLINE в glTF и ждать что Luanti поймёт

Правильный порядок загрузки

1. Минимальные зависимости (mobs_redo, player_api, etc)

Lua 5.1 подводные камни

Luanti работает на LuaJIT (Lua 5.1). Не все фичи современного Lua доступны. Вот что чаще всего ломает код.

1. Метод с двоеточием и and — нельзя

-- ❌ КРАШИТ
local id = entity:get_id and entity:get_id()

-- ✅ ПРАВИЛЬНО
local id
if entity.get_id then id = entity:get_id() end

Двоеточие в Lua — это синтаксис вызова функции с self, оно не может существовать без ().

2. Бинарные операторы — нет

ОператорLua 5.1Lua 5.3+
a << b❌✅
a >> b❌✅
a & b❌✅
a | b❌✅
a ~ b (xor)❌✅
~a (bnot)❌✅
~= (не равно)✅✅
// (цел. деление)❌✅

Если реально нужны биты — local bit = require("bit") (LuaJIT встроенная).

3. Нет goto (в некоторых сборках)

LuaJIT может не иметь goto. Избегай.

4. Хеш << / & в шуме — ломает

Классический GLSL-хеш не переносится. Используй sin-хеш:

local function hash1(n)
  local x = math.sin(n * 12.9898) * 43758.5453
  return 2 * (x - math.floor(x)) - 1
end

FAQ

Можно ли использовать PrapsLib на игроке?

Технически да. См. Реанимация игрока. Основная боль — синхронизация в MP и совместимость с wielditem.

Как добавить свой easing?

prapslib.easing.myEase = function(t) return t * t * t end

Как добавить свой Molang query?

prapslib.molang.register_query("my_stat", function(ctx)
  return ctx.entity and ctx.entity.rage or 0
end)

Почему анимация слишком быстрая?

animation_length в JSON — в секундах. Если в Blockbench было в тиках — умножь на 0.05.

Как заставить работать с 3d_armor?

Используй стандартные имена костей (Body, Head) в модели. Тогда 3d_armor привяжется сам.

Можно ли смешать PrapsLib с mobs_redo?

Да — использовать mobs_redo для AI, PrapsLib для анимаций. mobs_redo пишет в on_step, PrapsLib — в globalstep, побеждает PrapsLib.

Как сделать IK-ноги как у паука?

См. Рецепт: Паук на IK.

Что делать с предупреждением CUBICSPLINE в glTF?

Luanti его игнорирует. Перенеси easing из glTF в .animation.json в поле easing. Или используй LINEAR в glTF.

Как перезагрузить анимации без перезапуска сервера?

prapslib.clear_cache()
-- При следующем register_entity_data подтянет свежие файлы
